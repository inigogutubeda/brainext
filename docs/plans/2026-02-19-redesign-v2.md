# Brainext V2 Design Document

**Date:** 2026-02-19
**Status:** Approved
**Scope:** Full UI/UX redesign + profile-aware ritual flows + focus mode

---

## 1. Vision

Brainext helps freelancers, entrepreneurs, creatives, and business owners ask one question every day:

> "¿Tiene sentido, hoy, en qué estoy invirtiendo mi tiempo y energía?"

V2 makes the product feel like a premium daily ritual tool — warm, human, and opinionated — rather than a generic productivity app. Every interaction connects to the daily cycle: morning intention → day → evening reflection → feeds tomorrow.

---

## 2. The Daily Loop

```
Mañana → estableces intención con contexto de tus objetivos
   ↓
Día → tu foco es visible en home, te recuerda qué decidiste
   ↓
Tarde/noche → cierras con reflexión, comparas intención vs realidad
   ↓
Mañana siguiente → home muestra el cierre de ayer antes de pedir el foco nuevo
   ↓
Semana → revisión integra todo lo capturado en los cierres
```

This loop is the product. Every screen either serves or feeds it.

## 3. Design System

### Color Palette

| Token | Value | Use |
|---|---|---|
| `bg-cream` | `#FAF7F2` | App background |
| `surface` | `#FFFFFF` | Cards, modals |
| `text-primary` | `#1C1917` | Headings, body |
| `text-secondary` | `#78716C` | Labels, hints |
| `accent` | `#D97706` | Primary CTAs, active states |
| `border` | `#E7E5E0` | Card borders, dividers |
| `destructive` | `#DC2626` | Errors, close actions |

### Typography

- **Headings:** 24–28px, font-weight 700, warm near-black, generous letter-spacing
- **Section labels:** 11px, all-caps, `text-secondary`, tracked — notebook section feel
- **Body:** 15–16px, line-height 1.6, readable and unhurried
- **CTAs:** 15px, font-weight 600, centered

### Components

- **Cards:** `bg-white rounded-3xl` with `shadow-sm` — elevated, not flat
- **Primary button:** Full-width, `bg-amber-600 rounded-2xl py-4` — solid amber
- **Secondary button:** Full-width, `border border-stone-300 rounded-2xl py-4`
- **Text inputs:** `bg-stone-100 rounded-xl px-4 py-3` — soft filled, no hard border
- **Multiline inputs:** Same fill, `min-h-24`, grows with content
- **Section headers:** All-caps stone-400 label above content group
- **Picker/selector cards:** Tappable cards with amber checkmark when selected

### Motion

- **Screen transitions:** Horizontal slide for tab navigation, vertical slide-up for rituals/modals
- **Card press:** Subtle spring scale (0.97 → 1.0)
- **Save confirmation:** Fade + scale, brief amber flash on success
- **Ritual entry:** Slide up from bottom, covers tabs entirely

## 4. Navigation Architecture

### Bottom Tabs (3)

```
[ Hoy ]    [ Objetivos ]    [ Proyectos ]
```

- Active tab: amber underline indicator, not filled background
- Tab labels only, no icons
- Tabs hidden during ritual flows (morning, evening, weekly)

### Ritual Flows

Morning ritual, Evening journal, and Weekly review open as **full-screen bottom sheet modals** that slide up over the home screen. The tab bar disappears. A subtle `×` dismiss is available but completing the ritual is the natural exit.

### Goals + Projects contextual panels

During the morning ritual's focus selection step, active goals and projects surface as a **dismissible bottom panel** — the user never leaves the ritual to reference their system.

3. Secondary focus input (optional)

| Emprendedor | "¿Qué mueve la aguja de tu negocio hoy?" | "¿Estás construyendo o apagando fuegos?" | "¿Esto acerca tu visión o la pospone?" |

## 8. Focus Mode — "Modo Foco"

A cross-platform distraction-reduction feature that activates during declared focus time.

### Entry point

After completing the morning ritual, a prompt appears:

```
¿Quieres activar el Modo Foco?
Protege tu tiempo de las distracciones.

[ Activar por 90 min ]  [ Ahora no ]
```

User can set duration (25 / 60 / 90 / 120 min) or a custom time.

### iOS Implementation

True app blocking is not possible without Apple's `FamilyControls` entitlement (restricted to parental control apps). Instead:

- **In-app focus timer:** Full-screen ambient timer screen in the app. Warm background, focus text visible, soft countdown. Discourages leaving.
- **Return accountability:** If user leaves the app and returns during focus time, a prompt fires: "Estuviste fuera X minutos. ¿Qué pasó?" with 3 quick options: "Me distrajeron" / "Era necesario" / "Me perdí". Answer is stored in the journal for the evening reflection.
- **Notification reminder:** A persistent notification shows remaining focus time, tapping it returns to the focus screen.
- **Screen Time deep link:** Optional guidance to set Screen Time limits manually (links to iOS Settings > Screen Time).

### Android Implementation

- **App blocking via Accessibility Service:** Uses `UsageStatsManager` + Accessibility Service to detect and block specified apps during focus time. User must grant permissions on first use (guided setup screen explains why).
- **Blocked app overlay:** When user opens a blocked app, Brainext shows a full-screen overlay: "Estás en Modo Foco hasta las [hora]. ¿Salir del foco?" with friction to confirm.
- **Same return accountability** as iOS when focus ends or is broken.
- **Requires custom native module** — not available in Expo managed workflow. Needs `expo-dev-client` or bare workflow.

### Technical constraint

The Android blocking feature requires ejecting from Expo managed workflow (or using `expo-dev-client` with a custom native module). This is **Phase 2** — the UX and iOS implementation are built in V2, Android blocking is a follow-up native module task.

### Focus mode data

A new `FocusSession` entity (Phase 2 schema addition):
```
focus_session:
  - id, user_id, date
  - started_at, ended_at, planned_duration_min
  - breaks: [{ left_at, returned_at, reason }]
  - completed: boolean
```

For V2, break tracking is stored locally only (no Supabase sync) to keep schema changes minimal.

```ts
// Before
export interface GuidedAnswers {
  what_happened: string;

// After
export interface GuidedAnswers {
  q1: string;
  q2: string;
  q3: string;
  alignment_score: 1 | 2 | 3 | 4 | 5;
```

`guided_answers` is a JSONB column — no migration needed, the shape just changes in the app layer.

## 10. RLS Fix (First Task of Implementation)

Common failures in current setup:
- `upsert` on `daily_focus` and `journal_entries` requires explicit `INSERT` + `UPDATE` policies, not just `SELECT`
- `profiles` table may be missing insert policy for new user trigger
- `goals` and `projects` insert policies may not cover all operations

Fix: audit all 6 tables, ensure each has explicit policies for `SELECT`, `INSERT`, `UPDATE`, `DELETE` scoped to `auth.uid() = user_id`.

## 11. Out of Scope for V2
